# 底盘最小运动版：删减审阅

基线：`143e14c`，`main`。工作分支：`chassis/minimal-motion`。
本文件是实现前的删减方案；当前分支尚未删除运动功能。

## 目标与实际前提

第一版目标：机器人正放，从已有整备姿态进入站立，在平整地面低速前后运动、转向、松杆保持。
保留 CAN3 上板遥控和现有机构/电机接线。默认先用 Lmin=0.16 m 固定平均腿长；
roll PID 仍可产生左右差动腿长，因此两条腿的实际长度并不恒等于 Lmin。
不把翻身、飞坡、腾空落地、跳跃、爬阶或高速小陀螺作为验收目标。

“最小”先缩减行为和依赖，再考虑替换估计器/控制器。不能同时删功能、换状态估计、
重拟合 LQR、改电机单位，否则发生站立问题时无法定位来源。

## 建议保留

| 内容 | 实际理由与最小形态 |
| --- | --- |
| AHRS、完整 imu::state、电机反馈快照 | 是观测入口；继续短临界区复制一次，各状态 const& 使用。 |
| 左右镜像、DM 速度 1/9、轮电流尺度 | 属于机构和驱动协议的对应关系，不能当作经验 trick 删除。 |
| VMC、J/JT 与虚拟腿解算 | LQR 虚拟腿力矩、腿长 PID 轴向力必须映射为两关节力矩。 |
| 现有 odom | LQR 需要 x/v；它不是跳跃专属代码。暂不改成裸轮速积分，也不顺手修改 Q。 |
| LOW LQR 的完整 10 状态、4 输出 | 当前站立/行走闭环基础；不能只留下轮力矩而丢掉虚拟腿力矩。 |
| 按实际左右腿长求 K | 即使固定平均腿长，roll 控制和机构动态仍会造成腿长变化；不能无验证地冻结 K。 |
| 左右 len PID、roll PID | len 控制支撑与高度，roll 输出差动腿长；不新增 MPC/LESO 接口。 |
| alpha_eq(len) | 机构平衡倾角，不等于可删除的经验偏置。旧多项式先保留，来源疑点继续记录。 |
| Gff 与 Fs | 重力前馈和真实弹簧的等效支撑。当前轴向命令为 PID + Gff - Fs；直接删减会改变支撑。 |
| 简单速度/腿长斜坡、死区、x/yaw 保持 | 防止参考突变，并提供松杆停住的目标语义；每类保留一套直接实现。 |
| 有限幅值、电机输出开关、命令/IMU 有效性、必要几何检查 | 保留已有基本条件，不增加保护状态机或重复检查。 |
| debug/tuning、Python 模型生成与测试 | 保留真实 ref/fdb/输出和参数可修改性；删除功能时同步删除其调试字段。 |
| command/control 两个线程与 topics | 解耦输入和控制已有清晰边界，不为了减少文件把协议放进控制状态机。 |

Fs 计算与 normal_force 估计必须区分：前者直接进入正常站立轴向力，后者主要用于离地判据。
不能为了删除 OFFGROUND 把弹簧支撑一起删掉。

## 状态机建议：先保留四个直观状态

`RELAX → FLATTEN → NEUTRAL → NORMAL`，停机或现有有效性条件失败回到 RELAX。

- RELAX：零输出/复位，正放且启动命令有效后开始整备；删除自动转入 RECOVER 的路径。
- FLATTEN：保留旧机构展平路线。不能假设任意静止关节姿态可以直接进入 LQR 平衡。
- NEUTRAL：保留虚拟腿扶正和低腿长整备；达到条件后进入 NORMAL。
- NORMAL：只做平衡、低速移动和转向。

不建议第一刀就改成 RELAX/NORMAL 两态，也不把 FLATTEN/NEUTRAL 藏进一个含多个 phase 的
“通用 ready 控制器”。两态版本需要明确“人工把腿摆到可平衡姿态”的操作前提；当前没有这项约定。
run_* 和 state_context 继续直接使用，状态增减只改相应分支和持久变量。

整备期的轮力矩 ±1.5、phi 方向选择和腿长收缩比例先保留：它们是启动运动的一部分。
要删除这些，需要先验证机器人正放时实际腿姿，以及是否可以不借助轮运动完成扶正。
删除翻身不等于可以删除全部 phi 控制与连续角目标。

## 可以简化、但不能直接归零的 trick

| 当前实现 | 建议 |
| --- | --- |
| NORMAL 的 alpha_eq + 0.03 | 将 0.03 暴露为明确的 alpha trim 参数，先保留基线值；对比站立后的偏移和电流再决定是否置零。alpha_eq 本体不删。 |
| 首次 5000/-1500，首次 NORMAL 后永久改 2000/-400 的 len PID | 改为整备/正常两个显式参数组，按执行状态选择，删 running_gains_ 的历史开关。第一版不贸然统一为一套参数。 |
| airprotect_count_ 同时承担运动使能和离地等待 | 删除离地用途；NORMAL 初期速度禁止可暂保留为一个用途明确的 settle 计时，之后实测再决定是否删掉。 |
| 腿长相关速度缩放/斜坡步长 | 固定低腿长下可删，保留一个低速上限与一个固定斜坡。重新开放升腿功能时重新评估。 |
| vy 触发机体转向 90°后行走 | 第一版可只保留前后输入和现有朝向跟随；不要把 vy 偷改成 yaw rate，这会改变上板操作语义。 |
| 掉电/倾倒条件 | 保留现有基本退出路径。删除恢复行为后不增加自动重试。原阈值和不对称判断是否合理应单独审阅。 |

## yaw、拨弹和 C1：当前依赖不能忽略

当前 command 使用 yaw 电机位置计算上板/底盘相对方向，且 recovered 后受到 yaw_ready 门控；
C1 initialized 位也来自 yaw_ready。直接移除 yaw 电机会造成无法使能或错误转向。

建议本次第一阶段保留独立 yaw 兼容业务：反馈、对中、上板电流命令、C1 原语义。
去掉与小陀螺相关的 +5000，保留普通朝向跟随。这样最小底盘运动可以继续使用现有上板。
不要用写死 yaw_ready=true 冒充已完成对中。

拨弹与底盘闭环没有直接关系，是进一步删减的候选：若本分支确定只调底盘，可删除
trigger PID/实例/注册/反馈/发送与 robot 配置，B2 仍保持原布局并忽略 trigger 字节。
但此前用户明确要求保留 yaw 与拨弹业务，因此这里列为范围变更建议，本轮不默默删除。

Referee 也要分开处理：运动缩放可以删；C1 中 robot_id/level/heat 等字段当前来自 Referee。
第一阶段保留这条轻量转发及公共服务，不把虚假的裁判字段当作真实状态发送。
若后续把上板也切换为专用底盘测试协议，才一起取消 yaw/C1/Referee 依赖。

## 文件与实施顺序

1. `chassis.cpp/.hpp`、`robot_types.hpp`：删除五个特殊状态和事件；保留四态整备/平衡主链。
2. `command.cpp/.hpp`：固定低腿长、删跳跃/旋转/飞坡/爬阶与功率缩放，保留明确的输入、参考生成和保持。
3. `pendulum.cpp`：删除无消费者的 normal_force 估计和差分历史；保留几何、速度、Fs、VMC 及需要 watch 的力反馈。
4. `robot_io.cpp/.hpp`、`robot.cpp`、topics/配置：一起移除 TOF/SuperCap/动作事件接入；保持 CAN3 包布局与现有 yaw/C1 依赖。
5. `chassis_model.hpp`、`robot_debug.hpp`：删除专属参数，保留机构参数、单位换算、控制 tuning 三组清晰分区；不引入 JSON 控制算法配置。
6. 同步修改回归测试和文档，不留满屏功能开关、死分支或旧接口占位。历史完整实现由基线 commit 保存。

验证应包括：四态可达和整备退出、NORMAL 静态/低速输出、松杆保持、姿态镜像与 VMC、
phi 连续角方向、tuning 生效、失效回 RELAX，以及禁用 B2 动作位确实不改变运动。
构建 H723 Debug/Release；模型/单位兼容测试保留。删除功能对应测试同步删除或改为忽略输入测试。
本轮只做范围审阅，没有新固件编译、烧录或实机结论。
